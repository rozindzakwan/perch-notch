# Glass UI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Restyle every Perch surface to the approved Glass look, with Inter type, vector icons, springy motion and in-notch notification banners, inside the existing footprint budgets.

**Architecture:** Keep the CPU renderer (tiny-skia + fontdue). Add a token layer (`theme.rs`, `tokens.rs`), reusable components (`crates/ui/src/glass/`), cached shadow/glow masks, a spring module in `perch-core`, and a banner queue in the model. Views stay plain data (ADR-011); the renderer paints them and returns hits. Every animation is deadline-driven and stops when settled.

**Tech Stack:** Rust 1.85, winit 0.30, softbuffer, tiny-skia 0.11, fontdue, windows 0.58 (DWM), x11rb.

**Spec:** `docs/superpowers/specs/2026-11-14-glass-ui-design.md` (read it first; mockups in `docs/design/glass-screens.html`).

## Global Constraints

- Idle RAM < 40 MB; cold start (first frame) < 300 ms; release binary < 15 MB on Windows and Linux.
- Idle CPU 0: no deadline once every animation has settled; no animation while idle, including while music plays (pill equaliser bars are static).
- No new GPU, web view or UI-toolkit dependency. New crates only if unavoidable; fonts are data files.
- Surface fill rgba(18, 20, 28, 0.58) with OS blur, rgba(18, 20, 28, 0.88) without; light: rgba(246, 247, 250, 0.72) / 0.92.
- Hairline border 1 px rgba(255,255,255,0.16); inner top highlight 1 px rgba(255,255,255,0.16).
- Radii: panel 26, banner 22, rows 14, cover 16, pill/tabs/buttons/avatars fully round. Spacing on a 4-pt grid; panel padding 12; rows 34 (one line) / 42 (two lines).
- Type (Inter): title 15/700, body 12.5/500, secondary 12/400 at 62 %, caption 10.5/500; numbers tabular.
- Accents: mail #5B8CFF→#8A5BFF; tasks #2BB673→#7EE0A1; coral fallback #FF6F91→#FFB199; status ok #5BD38A, error #FF6B6B.
- Motion: open spring ≈ 320 ms settle, overshoot ≤ 4 %; close ease-out ≈ 180 ms, no overshoot; content fade 140 ms + 6 px slide after 40 % open; tab highlight spring ≈ 220 ms, content cross-fade 120 ms; hover fade 100 ms. Reduced motion (OS setting) = instant changes or short fades only.
- Banner ≈ 300 × 56 logical, 4 s (paused while hovered), ≤ 3 queued then merged; none while expanded; none while fullscreen (show the latest one when visible again).
- Config: `[notifications] in_notch = true, system = false`; `[appearance] blur = "auto" | "off"`; legacy defaults (`expanded_width = 480`, `expanded_height = 200`, `animation_ms = 180`) map to the new defaults (≈ 380 × 300, 320 ms).
- Avatars: initials only, never fetched. Read-only mail guarantees unchanged.
- Shadows: ≤ 4 px around the collapsed pill (no click-stealing margin); ≈ 12 px when expanded.
- Commit messages carry no `Co-Authored-By` or other AI attribution line (user preference).

## Review Focus

1. **Very long or non-Latin text** (300-character subject, emoji, Cyrillic sender, long track title): must ellipsize inside its box; nothing overflows into neighbours. Test in Task 10 and Task 8.
2. **Fractional DPI (1.25×, 1.5×)**: shapes must have no gaps or stray pixels outside the rounded outline. Test in Task 7.
3. **Bursts and awkward timing for banners**: ten mails at once, a banner arriving while the user hovers or the panel is opening, during fullscreen. Expect merged counts, no banner while open, one deferred banner after fullscreen. Test in Task 13.
4. **Hover reversal mid-animation** (leave during the open spring's overshoot, re-enter while closing): size must change continuously, never jump, and end in the right state. Test in Task 6.
5. **Light theme and missing data** (no player, no cover, empty lists, no accounts): every screen renders with fallback accents and empty-state text, readable in light mode. Test in Task 9 and Task 11.
